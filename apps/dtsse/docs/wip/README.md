# DTSSE work-in-progress documentation

Unreleased or exploratory platform work from the DTSSE / Decentralisation team, written up
early so service teams can see what is coming and start integrating before it is fully
productionised. **Nothing here is in the core docs yet.** `scripts/docs-index` only scans
the four Diátaxis quadrants, so these pages never appear in `DOCS.md` and are not found by
`/cft-explain` or `/cft-how-to`. When a piece of work is productionised its page is moved
into the target product's docs tree with `/dtsse:wip-promote`.

Managed by the `dtsse` team plugin (`apps/dtsse/.claude/`): `/dtsse:wip-add`,
`/dtsse:wip-status`, `/dtsse:wip-promote`. Without the plugin, run
`apps/dtsse/.claude/scripts/wip --help` directly.

## Status vocabulary

| `status` | Meaning | Safe to integrate? |
|---|---|---|
| `exploratory` | A design or spike. The shape may still change. | No. Talk to the owner first. |
| `in-progress` | Being built; the contract is mostly settled. | Only where `integrate_now: true`. |
| `ready` | Merged and deployed; waiting to be promoted to core docs. | Yes. |

`integrate_now` is the owner's explicit statement that a service team can build against the
current contract. Treat it as the answer to "can we start yet?".

## Lifecycle

1. `wip new <slug>` scaffolds a page from the template with the frontmatter below.
2. The owner keeps the page current, bumping `last_updated` (`wip touch`) as the work changes.
   `wip stale` lists pages that have gone quiet.
3. When the promotion criteria at the foot of the page are met, set `status: ready`.
4. `wip promote <slug>` moves the page into `apps/<product>/docs/<quadrant>/`, rewrites the
   frontmatter to the core schema, regenerates this index and `DOCS.md`. Prose that hedges
   ("this may change", "not yet deployed") is removed as part of promotion, and the page is
   linked from the product's `docs/README.md`.
